## The report

# Review of `docs/design/notes/m3-u2-sessions.md` (U2) and decisions rows 38, 39

Reviewed in `/tmp/u2design`, branch `feat/301-m3-u2-sessions` (commit 07983fd over `main`). Read only; nothing run.

## Verdict

**Build after changes.** The session table (S1 to S5) and the window arithmetic for a fresh burst are sound. Four things must be settled first. (1) D1/D2 are only exhaustive if the S5 lock is the serialisation point between `storeInbound` and `finishTurn`, which the note does not say (N1). (2) S11 does not achieve what row 39 promises, because the batch and the reopened messages cross the session boundary (N2). (3) D2 silently reverses decisions row 3 and changes an M2 test's outcome (N3). (4) Discarding at step 4 loses a ready answer for messages that end at steps 5 to 11, and the maintainer is not asked (N4). The test plan cannot be written as described (N9), and the migration section is too thin to implement (N13, N14).

### Answers to the questions not carried by a finding

- **Q1, S3 `ended_at` with an outbound last message:** consistent with the glossary, given S8/S9. `started_at` is not defined beyond "the time the row is stored"; say it equals the first message's `created_at` (one clock read, returned from the insert), also for the backfill.
- **Q3, `window-closed`:** no collision with the `error_code` check (`^[A-Za-z0-9_-]{1,40}$`), the names check (no list of error codes exists, #278) or the send policy (no call is made). It shares a namespace with the channel's codes; the stand-in uses lower-case words too (`not-authorised`). `expired` is the precedent for `failed` without a call; `withheld` is defined for other classes. "Never moved back" is right under stored time.
